# 鸿蒙小车蓝牙遥控
## 一、项目目标

用手机通过蓝牙（BLE）遥控小车移动：前进、后退、左转、右转、停止、调速。

## 二、整体架构（数据通路）

```
手机App ──BLE──> JDY-16 ──UART──> Hi3861 ──UART──> STM32F103 ──PWM──> L9110S×2 ──> 左右电机
                 (透传)          (决策/转发)        (电机PI闭环)
```

**关键点：蓝牙数据必须经过 Hi3861。** 原理图上 JDY-16 的串口接的是 Hi3861 的引脚，STM32 没有任何 UART 直连蓝牙模块。

## 三、原理图分析结论

### 硬件连接（原理图实测）

| 连接 | 说明 |
|---|---|
| JDY-16 TXD → Hi3861 **IO01** | 蓝牙数据进入 Hi3861 |
| Hi3861 **IO11** → STM32 **PA10** | 指令下发（UART2 → USART1） |
| Hi3861 **IO12** ← STM32 **PA9** | 状态回传 |
| 电机驱动 | L9110S×2，左电机 U1→JP1，右电机 U2→JP2 |

### 两芯片的 UART 分工

**Hi3861（3 路）：**

| UART | 引脚 | 用途 |
|---|---|---|
| UART0 | IO03/IO04 | 调试日志（经 SW2 切换 → CH340 → Type-C） |
| UART1 | IO00/IO01 | **接 JDY-16 蓝牙模块** |
| UART2 | IO11/IO12 | 接 STM32，发电机控制帧 |

**STM32F103（3 路）：**

| UART | 引脚 | 用途 |
|---|---|---|
| USART1 | PA9/PA10 | 接 Hi3861，收控制帧 → PI 闭环 |
| USART2 | PA2/PA3 | NFC 模块接口（JP7） |
| USART3 | PB10/PB11 | 调试输出排针（JP10） |

> SW2 是"USB 串口切换"开关：拨到一边电脑看 Hi3861 日志（UART0），拨到另一边可监听 Hi3861↔STM32 通信（UART2）。

### Hi3861↔STM32 通信协议

6 字节帧：

```
[0xFC] [A方向] [A速度] [B方向] [B速度] [0xFD]
 帧头   0正/1反  0~150   0正/1反  0~150   帧尾
```

速度值 = 实际转速(rad/s) × 100，范围 -150~150。

## 四、代码实现

### 1. STM32端

- `uart.c`：`USART1_IRQHandler` 解析 0xFC..0xFD 帧 → 更新目标转速；
- `control_system.c`：增量式 PI 闭环；
- `motor.c`：TIM4 输出 PWM（PB6/PB7），PB13/PB14 控方向。

### 2. Hi3861端

核心逻辑：UART1 收单字符指令 → 转换为电机参数 → UART2 组帧发给 STM32。

**指令集（手机端约定）：**

| 字符 | 功能 | 字符 | 功能 |
|---|---|---|---|
| `W` | 前进 | `O` | 停止 |
| `S` | 后退 | `1`~`5` | 速度档位 40/70/100/125/150 |
| `A` / `D` | 左 / 右转 | `+` / `-` | 速度微调 ±10 |

**调速的实现思路**：速度不写在方向函数里，而是用全局变量 `g_speed`；另用 `g_last_cmd` 记住当前运动状态，调速后立即按原状态重新下发，实现"边走边调"。

**初始化流程**（`Control()`）：

```c
GpioInit();
IoSetFunc(GPIO_0, UART1_TXD);  IoSetFunc(GPIO_1, UART1_RXD);   // 蓝牙口
UartInit(UART1, 9600);                                          // 按模块实际值
IoSetFunc(GPIO_11, UART2_TXD); IoSetFunc(GPIO_12, UART2_RXD);  // STM32 口
UartInit(UART2, 115200);
osThreadNew(car_mode_bluetooth, ...);                           // 创建接收任务
APP_FEATURE_INIT(Control);
```

## 五、过程中遇到的问题

### `APP_INIT_EVENT_NUM`

`APP_FEATURE_INIT` 是把初始化函数登记进一张**固定大小的启动表**，表容量由 `APP_INIT_EVENT_NUM` 决定。登记的入口超容量时，**超出的初始化函数被静默丢弃**——不报错、不崩溃，任务根本没被创建，表现为"功能失效"。

**解决**：把该宏改大。

**经验**：
- 注释掉 BUILD.gn 里不用的示例，它们不参与编译就不占表项；
- 一个入口可创建多个任务，大型项目建议只留一个入口统一创建任务；
- 功能不生效时，可以考虑这个宏。
